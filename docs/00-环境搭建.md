- 版本：**GmSSL 3.2.0**（官方 tag `v3.2.0`）

     报错（见 0.6 问题 1），**弃用**；
  2. 宿主机下载官方源码 `https://github.com/guanzhi/GmSSL/archive/refs/tags/v3.2.0.tar.gz`

     `sudo make install` → `sudo ldconfig`，一次走完。


## 0.6 问题与反思

### 问题 1：gitee 镜像 CMakeLists 与其源码树自相矛盾，`make install` 中途失败

- **现象**：`[100%] Built target gmssl` 之后
  `CMake Error ... file INSTALL cannot find "/home/20241422myh/GmSSL/thirdpart/gmssl/include/gmssl"`
- **排查**：`grep -rn thirdpart CMakeLists.txt cmake src` →
  镜像 `CMakeLists.txt:341` 引用 `thirdpart/gmssl/include/gmssl`，但整棵树里根本没有
  `thirdpart/` 目录（也无 `.gitmodules`）；对照官方 master 的 CMakeLists（1018 行），
  同一指令在 848 行、路径是正确的 `include/gmssl`，全文件无 `thirdpart`。
  结论：镜像与官方不同步，且自带残缺引用。
- **解决**：弃用镜像。宿主机拉官方 `v3.2.0` 源码包 → 共享目录 → VM 内重新编译安装。
- **教训**：`make` 成功 ≠ 安装成功；`make install` 的报错要用 `grep` 回源码找根因，
  不要只在 build 目录里打转。

### 问题 2：题面 `gmssl rand` 语法与 GmSSL 3.2.0 不符

- **现象**：按题面 `gmssl rand -hex 16` → `rand: illegal option '16'`
- **排查**：直接读源码 `tools/rand.c`，usage 为
  `[-hex] [-rdrand|-rdseed] -outlen num [-out file]`——长度参数改到了 `-outlen` 后面。
- **解决**：`gmssl rand -hex -outlen 16`（输出 32 个 hex 字符 = 16 字节）。
  题面按旧版语法书写，实验记录里保留这处差异说明。
